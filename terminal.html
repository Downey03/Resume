Case · Timezone API costAwaiting

Tracing a $2,000-a-month API bill to a cache eviction problem

$30–100 / month, down from ~$2,000
Problem
Our third-party timezone API was costing almost $2,000 every month, far more than the traffic should have needed.
Investigation
Timezone results were cached in a shared Redis that also held a lot of other data. As it filled up, Redis kept evicting the timezone entries, so most lookups missed and went to the paid API.
Fix
We gave the timezone cache its own dedicated Redis instance, so other data could no longer push it out.
Before · shared Rediskeys evicted → cache misses → paid API calls
→
After · dedicated Rediskeys stay cached → API only on real misses

Case · Structured loggingAwaiting

Making a legacy app debuggable with structured request logs

~30% less debugging time
across 6 core services

The legacy app was hard to debug in production. I added structured logging to Cloud Logging that records, for every request: who made it, the device, IP, URL and method, total latency, each upstream request with its own latency, and any errors.

Example log entry (illustrative values)
{
  "user": "u_48213",
  "device": "Android 14 · app 6.2.0",
  "ip": "203.0.113.24",
  "method": "GET",
  "url": "/api/v1/appointments",
  "latency_ms": 412,
  "upstream": [
    { "call": "datastore.query", "latency_ms": 88 },
    { "call": "timezone.lookup", "latency_ms": 301, "error": "timeout" }
  ]
}

I also used BigQuery log analysis and GCP usage data to find and remove idle resources.
